# PRODUCT_CAPABILITIES.md — Around 8-Domain Capability Matrix

This document defines the complete capability inventory across Around's **eight product domains** and tracks their maturity across four transparent completion tiers:
- **Schema & Backend Ready (UI Pending):** Database tables, triggers, and RLS policies are complete and verified in SQL, while client UI screens are scheduled for upcoming sprints.
- **Capability Complete:** Domain functionality, data contracts, and repository methods are implemented and unit-tested.
- **Product Integrated:** The domain connects seamlessly across multi-domain user journeys in both `lib/` and `supabase/`, ready for live staging verification.
- **Platform Ready:** Multi-user staging RLS verification, physical device testing, observability, and operational recovery procedures are verified in production/staging.

## 2. Milestone 50 Consolidated Architecture & Non-Negotiable Invariants

### Rule H — Editorial Data Over Bespoke Sub-Engines
All cultural themes (Tashkent Metro Mosaics, Soviet Modernist Architecture, Chaykhanas, Specialty Coffee Roasteries, Tandoor Bakeries, Artisan Craft, Puppet Theater) are represented as rich editorial data rows in `public.places`, `public.collections`, `public.collection_items`, and `public.curated_crawls` within `supabase/seed.sql` and `PlacesRepository`. Single-purpose table bloat and bespoke physical simulators have been completely eradicated.

### Rule I — Strict 4-Tab Surface & Navigation Cap
The canonical client retains exactly 4 top-level navigation tabs:
1. **Feed (`/feed`):** Chronological, finite friend drops and 24h stories.
2. **Explore (`/explore`):** Interactive PostGIS city map, category filters, and curated crawls.
3. **Saved (`/saved`):** Saved places shortlist, collaborative collections, and friend plans.
4. **Profile (`/profile`):** User identity and the unified **City Passport** (`District Passport Stamps` across 12 Tashkent districts + Metro lines, and `Territory Crowns` for neighborhood tastemakers).

### Deterministic Database Schema
The database schema consists of exactly 28 sequentially numbered migrations (`00001` through `00028`) with 100% Row-Level Security enforcement, dual-layer privacy (`hide_visits_history`), and `auth.uid()` derivation on all mutating RPCs.
